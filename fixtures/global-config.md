# 通用规则

这是我的全局 Claude Code 配置，适用于所有项目。

## 代码质量原则

- 始终编写干净、可维护、可读的代码
- 遵循 SOLID 原则
- 不要重复自己（DRY）
- 保持函数短小，只做一件事
- 给变量和函数起有意义的名字
- 添加适当的注释解释代码逻辑

## Git 工作流

- 提交前总是运行测试
- 每个提交应该是原子化的，只包含一个逻辑变更
- 提交信息要清晰描述变更内容
- 不要提交调试代码或 console.log
- 合并前 rebase 到最新主分支

## Seru 工具优先级

在任何项目中，优先使用 Serena 工具进行代码导航和编辑：

1. 用 `get_symbols_overview` 查看文件结构
2. 用 `find_symbol` 读取特定符号
3. 用 `find_referencing_symbols` 查找调用者
4. 用 `replace_symbol_body` 编辑符号

不要在代码文件上用内置 Read/Edit 工具，除非 Serena 工具不可用。

## 错误处理

- 永远不要忽略错误或异常
- 不要用空的 catch 块
- 错误要么处理，要么向上传递
- 总是记录错误上下文

## 不确定时

当不确定某个 API 或库的行为时，先查文档或源码，不要猜测。

## 测试优先

- 新功能先写测试（TDD）
- 测试要覆盖正常路径和边界情况
- 测试名字应该描述被测试的行为

## 文档

- 为公共 API 编写文档字符串
- README 要保持最新
- 记录重要的架构决策
